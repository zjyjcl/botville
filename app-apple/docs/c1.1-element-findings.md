# C1.1 Element 验证与问题收集

## 1. 摘要

关联 [C1.1 / #33](https://github.com/zjyjcl/botville/issues/33)，验收是**问题入待办**。本次已在 Element Web 实际点击注册、建群、邀请、私聊、发送文本、加密房、通知和加密设置；使用标准 Matrix API 作为另一端完成未加密群双向收发。第 5 节将发现落为可执行待办，不代表 C2.x 已实现或苹果 App 已通过端到端验收。

主要结论：

1. Continuwuity 的 bootstrap 注册可进入 Element，之后静态令牌可注册普通测试用户；首次引导需与普通注册区分，沿用已有 [#68](https://github.com/zjyjcl/botville/issues/68) 跟踪。
2. Element 私有群创建默认开启 E2EE，未加密房会持续提示；验证设备、恢复密钥和桌面通知提示也实际出现。C2.6 必须明确含 AI 会话的默认策略及提示文案。
3. 基础文本和房间链路可用，但 C0.1 尚缺建房/邀请、持久会话、未读/回执、媒体和推送；本地 HTTP 与 C0.1 的 HTTPS 校验也需要联调方案。
4. 认证媒体上传仍走 `/_matrix/media/v3/upload`；兼容性文档将它列入 `client/v1/media/*` 的写法需要更正。Element 中 bot 通知默认关闭；另一个 API 账号存在 `m.notice` 抑制规则，应按消息类型验收，不能外推到所有 AI 发言。
5. 验证末段本地服务消失，独立 GUI 密码登录与断线恢复未完成。APNs、多设备加密/恢复、苹果 App 与服务端产品功能仍未验收。

### 3.1 可复测步骤与 API 证据摘要

复测使用独立本地测试环境，先按 [server/README](../../server/README.md) 启动并核验 `/versions`；不要为了复测清空现有数据卷。参考 [smoke.py](../../server/tests/smoke.py) 的通用 UIA 流程，凭据在运行期提供，示例值仅用 `<registration-token>` / `<test-password>`。

1. 在 Element 注册页选本地 HS；用无效令牌验证错误分支，再用该部署当前阶段有效的令牌完成。首次引导需记录首账号归属；普通账号另用静态令牌。
2. 创建私有群时记录 E2EE 开关默认值；为 AI 场景测试群在创建时选择不加密。邀请另一个本地账号，由 API 接受；双方发送带方向标记的文本，分别断言 GUI 时间线和 API `/sync`。
3. 从 Start chat 创建 DM，发第一条消息后确认真实房间和 People 分类；API DM 测试另断言 `is_direct` 与双方 `m.direct`，不要只凭“房间里有两个人”判断 DM。
4. 创建另一个加密测试房，发送、刷新回读；真正的 E2EE 复测还必须加入第二个加密客户端，补设备验证与历史恢复。
5. 上传无敏感信息的小文件，认证下载并比较字节，再做无 token 负向检查；在群发送 `m.file` 并观察 Element 卡片。
6. 查看 Notifications 与 Encryption；记录实际弹出的验证/备份提示。最后再测独立密码登录、断线恢复及退出撤销，不能把注册自动登录算成独立密码登录成功。

## 4. 主要发现与 C 线差异

### 4.1 注册与登录：引导阶段不能隐藏在普通表单后

本次通过 bootstrap 令牌创建的 GUI 用户成为首管理员；之后静态配置令牌可注册普通用户。仓库兼容性说明已区分 bootstrap，但 `server/README.md` 的简述和 smoke 的固定令牌入口容易让操作者混淆阶段。首账号前静态令牌不生效是任务交接提供的已知线索，本次未重新构造干净数据卷验证；继续在 #68 收敛，不另开重复 issue。

C0.1 只支持密码登录，且 [Models.swift](../Sources/BotvilleCore/Models.swift) 拒绝非 HTTPS。Element 本轮普通窗口能够接本地 HTTP，不代表苹果端也能连。应提供受控本地 TLS/信任配置或明确的开发专用策略，生产默认仍要求 HTTPS；SSO/OIDC 按 `/login` 能力单独处理。

### 4.2 DM、群与 AI 关系不是同一种数据

Element 实测把 DM 放 People、群放 Rooms，输入完整 MXID 后有新联系人确认；首条 DM 消息发送前只是本地会话占位。C0.1 的 [MatrixService.swift](../Sources/BotvilleCore/MatrixService.swift) 当前只显示 `.joined`、按名称排序，没有邀请处理、DM 分类和建房流程。

本轮 GUI 与没有加密客户端密钥的 API 用户创建 DM，显示未加密；只记录该组合，不推论“Element 所有 DM 默认不加密”。AI 身份、好友关系、配对许可应来自 botville 约定，不能通过显示名、两名成员、`m.direct` 或 Element 的 People 分类推导。C2.2/C2.7 还要覆盖配对切断、审批与撤销，这些不是 Element 基础聊天验收的范围。

### 4.3 加密提示必须匹配产品语义

创建私有群时 E2EE 默认开启，页面提醒启用后不能关闭且多数 bot 不适用；[Element 官方建房说明](https://docs.element.io/latest/element-support/matrix-rooms/getting-started-creating-a-room/) 也说明加密不可逆。含 AI 房应在创建前明确策略，已有加密房引入不具备解密能力的 AI 时要给出可理解的处理路径，不能尝试“关闭加密”。

本次未加密群持续显示未加密提示；新账号出现设备验证提醒，加密房刷新后出现备份/恢复密钥提醒，可以 Later / Not now 暂缓。Encryption 设置显示 key storage 开启和创建恢复密钥入口；这只是 UI 状态，不证明服务器备份及新设备恢复成功。官方[恢复密钥说明](https://docs.element.io/latest/element-support/device-verification/how-to-ensure-you-have-a-recovery-key/) 是后续恢复流程参考。

C2.6 应清晰展示“含 AI 会话未启用 E2EE”的原因与可见性边界；不要把普通 HTTP 开发连接称为安全连接，也不要把“Everyone in this room is verified”（本轮单人房）当成双方设备验证。现有[兼容性报告 §3.5](../../docs/compat/homeserver-compat.md) 的谨慎发布范围仍需保留：本次不足以为 Rust HS 的完整 E2EE 放行。

### 4.4 同步、会话和时间线

C0.1 使用 `syncOnceV2` 连续标准 `/sync` 与 `inMemoryStore()`；退出进程重登，不具备 Element 本轮同一浏览器刷新后的持久恢复行为。Swift 绑定虽然来自 matrix-rust-sdk，不能直接假设 Element Web 与它使用相同同步、crypto 或存储实现。

服务器没有声明 MSC4186，本轮也未调用 Sliding Sync。C2.1 先验证所固定 SDK 的能力协商和回退；再用大量房间、邀请/离开、未读、断网、分页测试决定采用哪个同步路径，避免为了追平 Element UI 直接替换可用的 `/sync`。

### 4.5 媒体路径和通知语义需要独立验收

[Matrix 规范](https://spec.matrix.org/latest/client-server-api/#content-repository) 中，`config/download/thumbnail/preview_url` 使用认证的 `/_matrix/client/v1/media/*`，上传仍用 `/_matrix/media/v3/upload`。本轮分别实测正确上传成功、错误 `client/v1` 上传路径 `404`。应更正[兼容性报告 §2.1/§4.2](../../docs/compat/homeserver-compat.md)，不能通过开启旧版无认证下载绕过适配。

Element 通知设置分账号规则和设备/桌面开关。本轮 GUI 账号显示 bot 消息 Off，另一个 API 测试账号的默认规则抑制 `m.notice`；没有切换 UI 开关并对同一账号读回规则，二者直接映射未验证。`m.text` AI 发言是否通知仍取决于实际规则，必须按消息类型验证。网页权限和前台同步无法证明 APNs，C2.1/A1.2 需分别验证 pusher、Sygnal、APNs、通知深链与消息补拉；参考[官方设置说明](https://docs.element.io/latest/element-support/element-webdesktop-client-settings/element-settings/)。

## 6. 未测项、阻塞和残留

- **服务中途不可达**：末段 Element 独立无痕登录对 `localhost:8008` 和 `127.0.0.1:8008` 均显示 HS 无效；随后普通窗口显示 Offline，终端 curl 立即 connection refused，`docker ps` 无运行容器，`docker inspect botville-continuwuity-1` 返回 no such object。原因未确定；本任务没有据此修改服务或重启。GUI 独立密码登录及重连恢复保留未完成。
- **E2EE**：只验证加密房 UI 和同一浏览器刷新回读。没有第二加密设备、SAS/QR、备份内容/恢复、历史密钥丢失、跨客户端加密媒体结果。未将“未设置备份”的 `404` 当成服务器缺陷。
- **媒体**：文件卡显示与 API 字节往返有证据；GUI 文件选择/下载、图片缩略图、音视频、大文件、加密附件未测。
- **通知**：未启用浏览器通知权限；没有 APNs 凭据/签名设备/Sygnal 联测，不评估 <5s。只读 pushers 为空不说明服务器不支持推送。
- **范围**：未等 A1.1；未切换 Synapse/Tuwunel、未测联邦/配对、SSO/OIDC、真实 AI appservice、动态/关系/卡片授权后端、Apple 真机/最低系统。C0.1 原有编译/测试记录仅作历史上下文，本轮不重复宣称其通过。
- **残留与秘密**：测试账号、房间、消息、媒体曾写入本地 HS；未主动删除或清空数据卷，最终容器消失后卷内保留情况未知。API 进程退出前没有 logout，凭据在本地内存消失不等于服务端会话撤销；GUI 会话也未完成退出。临时凭据辅助页已关闭、监听停止、剪贴板替换为普通测试文字、测试密码变量清空。需要后续由部署维护流程处理测试数据/设备，不把本次记录当清理完成。
