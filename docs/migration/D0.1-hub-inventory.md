## 1. 概述与范围

现有中枢（OpenClaw/Hub）是所有者本机的个人消息中枢，承担 AI 完成通知、授权拍板、可靠投递、提醒晨报、多通道外发（iMessage、微信、飞书、webhook）与 Codex 派工等职责。botville 要把「通知 + 授权 + 完成监听」迁移为网关/App 内闭环（App 通知卡片 + 授权按钮 + 接入 SDK），并把私人渠道剥离为个人部署的外部插件。

盘点范围：中枢全部 28 个 Python 模块（模块→功能编号映射见附录 A）、hub 配置顶层键与 openclaw.json 顶层键（逐项处置见附录 B）、launchd 三个常驻服务（中枢网关服务、Mac 客户端、个人事件服务，逐条见第 2 节 F20/F23/F24）与三个运行时目录（个人收发箱、本地语音、个人事件目录）。逐条给出 botville 替代方案与对应任务 ID，并标注迁移风险。

不覆盖范围：中枢配置具体值、密钥/令牌/凭据、钥匙串条目、内网地址与组网细节、设备标识与私人渠道账号、私人人设与口吻、私人联系人清单。以上属个人部署面，不进开源仓库，也不在本文展开。例外：第 5.1 节记录的是中枢的通用行为规则与默认参数（阈值、时间窗、重试次数、截断长度等），作为网关状态机与 D1.1 数据模型的迁移对照基线；不含凭据值、地址、端口、账号与组网细节。

脱敏核验方式：人工评审 + 关键词扫描双口径。维护一份私人代号关键词清单（历史 PA 名、个人事件服务名、本机插件名、个人 IM 渠道插件名、组网工具名及其常见变体），发布前对仓库全文扫描为零命中，并由盘点方人工复核泛化命名的一致性；A3.2 的密钥扫描与开源发布检查为最终验收关。

## 3. 通道原则

1. iMessage 与微信均为个人私有渠道，不进开源项目；由 D2.5 可选外部通知插件接口在个人部署承接（示例插件不含任何具体私人渠道）。
2. botville 通知不占用微信通道；并行期个人部署的 App/原有渠道双发按 D1.2 执行（个人部署走 iMessage）。
3. QQ/NapCat 直连不走境外代理（D2.3 验收含代理检查），对应功能条目见 F25。

## 4. 不迁移 / 保留在个人部署项

- 本地语音（F21）；个人收发箱与所有者入站话术分类（F17，当前 PAUSE）；iMessage 专用 iPhone 链路（F18）；微信通道及 24h 窗口维护（F16）；webhook 凭据与订阅（F15 的个人部分）。
- AI 会议室（F08）与晨报（F07）个人化程度高：开源版只保留可复用的通用能力（多 AI 群、订阅式通知），具体玩法留个人部署。
- 中枢本机部署面：launchd 常驻服务（中枢网关服务 F23、Mac 客户端 F24）、secrets、models、tools、约 30 个本机技能，以及本机客户端插件等本机插件。
- 中枢停服顺序与备份演练属 D3.1 个人部署执行项。

### 5.1 中枢维护方答复（只读核实，未含凭据值）

本节记录的是中枢的通用行为规则与默认参数（阈值、时间窗、重试次数、截断长度等），作为网关状态机与 D1.1 数据模型的迁移对照基线；不含凭据值、地址、端口、账号与组网细节。

1. **完成监听**：中枢 check 命令调用两个只读 watcher：Codex rollout watcher（事件落盘为 JSON 文件）与 ZCode 完成 watcher（读 ZCode CLI 日志与本地 SQLite，看 24h 内，异常报 degraded）。Kimi/Grok 仅有 agent-turn:* 通知键，无专门 watcher。可与 botville 订阅并行双跑，建议按事件 ID 去重、每天对账完成数。遗留：定时触发 check 的来源未找到（非 crontab/LaunchAgent，疑为网关内部），待核实。
2. **投递判定**：发送前落盘 sending，崩溃即 unknown 且同渠道不重放。ok 且内容以 sent_unconfirmed 开头 → 视为已送达（未确认）；其余 ok → confirmed。非 ok 且含 timeout/ambiguous/receipt-missing 或异常 → unknown（模糊，不重试，可走下一渠道）；其余 → failed/rejected（确认失败，可重试，同渠道 ≤3 次、间隔 ≥5 分钟）。全部 unknown 或满 3 次 → attention。iMessage：点发送前出错 → rejected；点后约 12s 轮询加一次复查，正文前 30 字匹配或出现新的已送达/已读 → confirmed；转短信 → sent_unconfirmed:went-sms；未送达 → rejected:not-delivered；其余 → sent_unconfirmed（不回退飞书）；正文超 3000 字截断。
3. **静默/整形**：quiet_hours 23:00–08:00，期间只走飞书，不走微信与眼镜端输出，失败告警也压住。渠道顺序 iMessage 优先、飞书回退，个人 AI 助手渠道全部暂停。整形只作用于 codex-turn:* / agent-turn:*：Codex 正文截 120 字并保留“/数字”菜单；同 agent 首条立即发，之后 10 分钟窗口合并摘要（≤600 字）；提问/审批/提醒/失败不整形。回放素材类型：按日 JSONL 通知明细、iMessage 发送日志 JSONL、agent 通知状态目录、Codex 事件目录、状态文件中的投递记录。晨报附当天通知明细（≤3000 字）。notification_policy 全量清单待 B3.2 前补充。
4. **微信 24h 窗口**：由中枢的窗口与健康模块维护，窗口时长 24h。目前全停（微信提醒关闭、个人 AI 助手出入站关闭、两个相关 LaunchAgent 已禁用）。建议并行期 botville 只读。已知前提：微信渠道留给个人 AI 助手。【待决策】中枢下线后微信窗口状态的维护归属。
5. **个人收发箱**：2026-11-03 因微信风控暂停，出入站开关均为 false、对应 plist 已禁用，暂停期间队列永不重发，未经所有者明确授权不得启用。恢复须在并行期方案确定后、经所有者授权进行，【待决策】恢复计划与时点及其与并行期方案的先后关系。
6. **健康探测**：10 分钟一探，连续 2 次异常判坏，告警冷却 6h，走普通通知路由，结果写健康状态 JSON。探测项：iMessage（手机自动化服务状态 + WDA 可驱动）、飞书（tenant token 获取）、代理客户端（控制器 + 节点延迟）、微信（固定 paused）。现状：iMessage 连续报 not-drivable，多半误报，修复未获授权；飞书、代理正常。建议 botville 复用前三项与阈值。
7. **凭据交接（只写方式）**：飞书应用凭据当前未纳入钥匙串，具体存储位置见个人部署私有文档；webhook 凭据（url/auth_header/secret）存于系统钥匙串（独立 service 条目），入站 webhook 关闭。交接：个人部署插件通过 security find-generic-password 读取同名钥匙串条目，不复制明文。轮换：飞书后台生成新密钥 → 写入钥匙串 → 切换生效 → 废弃旧密钥。建议 appSecret 也迁入钥匙串（【待决策】，需授权）。
8. **会议室/晨报**：会议室模块（口令“开会：主题”，AI 通过 hub meeting post 发言，结束发短摘要）；晨报模块（状态存于中枢状态文件）。【待决策】中枢下线后保留与否。
9. **个人事件服务**：本机 Python 服务，常驻 LaunchAgent（KeepAlive），仅在私有网络内提供游标拉取接口，需 token；家庭服务器每 5 分钟拉取，已有基线游标。与 B1.2 推送/订阅可并存（对齐游标）。【待决策】并存还是切换及时点。
10. **技能/插件**：通用类——11 个百炼系列技能（cli、docs-llm-wiki、finetune、gen、managed-agent、memory、model-recommend、protocol、sandbox、train-deploy、web-search）、抖音视频转文字技能，可评估进接入 SDK。私人/本机类——眼镜端输出规则、本机/多机 Codex 路由技能、临时腾讯文档技能、眼镜端插件套件、家庭服务器通知脚本，留个人部署。临时腾讯文档技能【待决策】去留。
11. **三个常驻服务**：中枢网关服务（KeepAlive，经 env wrapper 启动 node 进程，日志在用户 Library/Logs 下）；Mac 客户端（由 App 自己拉起，通过退出/打开 App 控制）；个人事件服务。方法：停 launchctl bootout gui/$(id -u)/<label>；起 launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/<label>.plist；重启 launchctl kickstart -k gui/$(id -u)/<label>；回滚：用中枢备份目录中的备份覆盖后 kickstart。任何启停实操须所有者单独授权。D3.1 备份清单：中枢运行时本地状态目录（约 6.7MB）、中枢配置 config.json、deployment.json、客户端主配置文件、3 个 plist 及 service-env 目录、个人事件服务目录及其 token、webhook 钥匙串条目。【待决策】下线停服时点。
12. **配置生效值**：agent_notifications = {enabled: true, zcode: {enabled: true}, phase: 1}（启用 agent 完成通知，含 ZCode，第一阶段）。reminder_defaults：day_time 09:00、before_minutes 30、on_day true、at_time false、timezone Asia/Shanghai（当天 09:00 提醒 + 事件前 30 分钟提醒；事件到点不单独提醒）。相关：ask_policy reminder_min 5、escalate_min 15；task_projects 存在项目前缀到项目名的映射。
